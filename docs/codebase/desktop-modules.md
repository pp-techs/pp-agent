# Desktop, daemon and agent-core modules

## Main process — `apps/desktop/src/main/`

| File                                                                             | Responsibility                                                                                                                                                                                                                                                                                                                                                                                |
| -------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `index.ts`                                                                       | App lifecycle and window; creates the `DaemonClient` and wires its callbacks (events to the renderer, notifier, tray/shortcut settings; `open_url` to the browser); asks for `get_snapshot` and runs the legacy vault migration after each connection; registers every `ipcMain.handle(IPC.*)`; opens only http(s) URLs externally; blocks in-window navigation; on quit disposes the client. |
| `daemon-client.ts`                                                               | `DaemonClient`: dials the socket with the token, handshakes (`hello`), spawns `dist/daemon.mjs run` detached with `ELECTRON_RUN_AS_NODE` when none listens, replaces a daemon of another protocol/version, correlates command ids with pending promises, reconnects 1 s after a drop, and shuts the daemon down on quit only when this app spawned it.                                        |
| `legacy-vault.ts`                                                                | Reads the old `credentials.json` (entries encrypted by `safeStorage`) and hands it to the daemon through `vault_import`, then deletes it; also `storeCredential`, which the `provider.json` migration uses.                                                                                                                                                                                   |
| `files.ts`                                                                       | Native dialogs and shell helpers: `pickFiles` (attachments), `pickSkill`, `pickFolder`, `openAgentFile`, `saveAgentFile`, `saveExportFile`, `openFolder`, `isInside` path check.                                                                                                                                                                                                              |
| `permissions.ts`                                                                 | Web permission handlers of the default session: the app window gets audio capture (voice input) and clipboard writes; everything else is denied.                                                                                                                                                                                                                                              |
| `panel/ipc.ts`, `panel/terminals.ts`, `panel/workspace-files.ts`                 | Side panel: IPC handlers with argument checks (folders must be workspaces), `TerminalHost` (node-pty shells, backlog), workspace listing, preview, reveal, attachment and watch. See [Side panel](../architecture/side-panel.md).                                                                                                                                                             |
| `browser/host.ts`, `browser/driver.ts`, `browser/address.ts`, `browser/cookies/` | Side panel browser: `BrowserHost` (a `WebContentsView` per tab, a partition per profile, navigation and permission rules), the `BrowserDriver` interface for future browser use, address and user agent helpers, and the Chromium / Firefox cookie readers.                                                                                                                                   |
| `legacy.ts`                                                                      | `migrateLegacyProvider`: converts the single-gateway settings of earlier versions before the daemon starts.                                                                                                                                                                                                                                                                                   |
| `tray.ts`, `shortcut.ts`, `notifications.ts`, `settings.ts`                      | The tray icon (closing the window hides it while it exists), the global shortcut, notifications when a run finishes or an approval is needed, and the slice of `settings.json` main reads for them.                                                                                                                                                                                           |
| `updates.ts`, `i18n.ts`                                                          | In-app updates (see [Release process](../code-standard/release-process.md)) and the language for main-process texts.                                                                                                                                                                                                                                                                          |

## Daemon — `apps/daemon/src/`

| File             | Responsibility                                                                                                                                                                                                                                                                         |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `index.ts`       | Entry: `run` (default, loads the host lazily), or `install` / `uninstall` / `status` / `help` without loading the Pi SDK.                                                                                                                                                              |
| `daemon.ts`      | `runDaemon`: creates the home folder, ensures the token, listens (single-instance guard), resolves the login-shell `PATH`, opens the vault, builds `AgentHost` and calls `init`; on `SIGTERM`/`SIGINT`/`shutdown` disposes the host (5 s limit) and closes the server. Logs to stdout. |
| `server.ts`      | `DaemonServer`: local socket server, `hello` authentication (token compared in constant time, 5 s deadline), `command` / `vault_import` / `shutdown` dispatch, event broadcast to every authenticated client, backpressure drop.                                                       |
| `framing.ts`     | `encodeFrame` and `FrameDecoder` for newline-delimited JSON (64 MiB per frame). Also used by main.                                                                                                                                                                                     |
| `paths.ts`       | `resolveDaemonPaths`: home (`PP_AGENT_HOME` or the OS `userData` location), endpoint, token file, log file and `AgentPaths`. Also used by main.                                                                                                                                        |
| `vault/index.ts` | `createVaultBackend`: the encrypted `vault.json` and master key resolution (`PP_AGENT_MASTER_KEY`, OS keyring, `vault.key`).                                                                                                                                                           |
| `service/`       | Login service backends behind `ServiceControl`: `launchd.ts`, `systemd.ts`, `windows-task.ts`, shared types, and `runner.ts` (`execFile`, no shell). `service-control.ts` builds the control for this install (runtime path, script, `PP_AGENT_*` environment).                        |
| `cli.ts`         | The `install`, `uninstall`, `status` and `help` commands. Exit codes: 0; 1 (failed, or `status` with the service not installed); 2 (unknown command).                                                                                                                                  |
| `shell-path.ts`  | Reads `PATH` from the login shell, because a daemon started by a service manager or the Dock has a minimal one and MCP commands such as `npx` need the real one.                                                                                                                       |

## Agent core — `packages/agent-core/src/`

| File                  | Responsibility                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| --------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `index.ts`            | `AgentHost`: `init(paths, locale)`, `handle(command)` switch over every agent command; session lifecycle (new/open/rename/delete/compact conversation), Pi event → `ChatMessage` mapping, approval gate, questions of `ask_user` (`requestQuestion`/`resolveQuestion`), `changed(scopes, apply)` which emits `settings_changed` and defers session reloads until a run settles; `gateway` (`ChannelGateway`) for chat channels; `importCredentials`; `dispose`. Takes a `HostEnvironment`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| `host-io.ts`          | The interfaces the daemon implements for the host: `HostOutput` (emit events, ask a client to open a URL), `VaultBackend`, `ServiceControl`, `HostEnvironment`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| `ipc.ts`              | `emit(AgentEvent)` to the configured `HostOutput` and `errorMessage` — the only path to the clients.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| `channels/`           | Chat channels. `types.ts` (`ChannelGateway`, `TurnHooks`, `ChannelService`: what the host needs from a chat app, found by the prefix of a chat key), `names.ts` (vault ids `channel:telegram`, `channel:zalo`), `settings.ts` (reads `channels` from settings.json), `shared/` (`bot-service.ts`: `BotService`, the start/stop/reconcile/pairing machinery both services extend; `pairing.ts` one-time codes; `split.ts` message splitting; `options.ts` / `sleep.ts` helpers; `testing.ts` fake gateway). `telegram/` — `channel.ts` (long polling, owner check, commands, media), `service.ts` (`TelegramService`), `approvals.ts` (inline Approve/Deny), `questions.ts` (`ask_user` buttons), `live-message.ts` (edited-in-place replies), `api.ts` (Bot API client), `format.ts` / `text.ts` (HTML formatting and texts). `zalo/` — `channel.ts`, `service.ts` (`ZaloService`), `prompts.ts` (approvals and questions answered by numbered replies, since Zalo has no buttons), `api.ts`, `text.ts`. |
| `channel-sessions.ts` | Pure pieces of chat conversations: `ChatSessionMap` (`channels.json`), `KeyedQueue` (one turn per chat), idle detection (`CHAT_IDLE_MS`, 30 min), the conversation title.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| `settings-store.ts`   | `SettingsStore`: reads/writes `settings.json` (`SettingsFile`: app settings, gateways, agents, workspaces, scheduled tasks, voice, channels). Files from before workspaces turn each folder an agent used into a workspace on load.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| `credentials.ts`      | `VaultCredentialStore`: Pi `CredentialStore` backed by the daemon's `VaultBackend`, with a local cache.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| `providers.ts`        | Providers and gateways: URL normalization, gateway ids, registering gateways with Pi (`syncGateways`), fetching gateway models, model summaries/lookup, `listProviders`, sign-in `authInteraction`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| `auth-prompts.ts`     | `AuthPrompts`: pending questions of a sign-in flow, emitted as `auth_prompt` and answered by `respond_auth_prompt`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| `agents.ts`           | Agent profiles: `DEFAULT_AGENT`, validation, ids/unique names, export/import file format, the agent's system-prompt section, tool options for the agent editor.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| `workspaces.ts`       | Workspace profiles: `DEFAULT_WORKSPACE`, validation, ids/unique names, folder preparation (`prepareFolder`), matching a session's `cwd` to its workspace (`workspaceForCwd`), the workspace's system-prompt section, migration from agent folders.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| `tools.ts`            | `SYSTEM_PROMPT`, built-in `AGENT_TOOLS` (incl. example `currentDateTimeTool`, shell tool `bash`/`powershell`), tool tier classification, tool policy resolution (`toolRule`), active tool selection per agent, MCP tool-name parsing, `describeToolCall` for approval cards.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| `web/`                | Web search and fetch: `providers.ts` (SearXNG, Serper, Tavily, Brave, Exa, webclaw, DuckDuckGo adapters; Exa without a key and DuckDuckGo need none), `search.ts` (`WebSearchService`: config, vault keys, the person's providers first then the keyless fallback, test), `webclaw.ts` (HTML → Markdown with the bundled binary), `fetch.ts` (SSRF-guarded page fetch and text extraction), `tools.ts` (`web_search`, `web_fetch`), `config.ts` (settings.json `webSearch` reader).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| `memory.ts`           | Long-term memory: pure note logic (places, caps, dedupe, search, `## Memory` prompt section), `MemoryStore` (the `MEMORY.md` files), and the `memory_*` tools. Each note lives everywhere or in one workspace only.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| `ask.ts`              | `ask_user`: schema, validation of questions and answers, result text, prompt section; the host decides how a question is shown (`SessionScope.askUser`).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| `sessions-tool.ts`    | `sessions`: read-only tool (actions `list`, `history`, `peers`) that shows saved conversations and the chats a message can go to; limited to the running session in scheduled runs.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| `session-index.ts`    | Pure parts of `sessions`: session ids, kind (`chat`, `task`, `window`), filtering by visibility, history text, and the `## Where you are` prompt section.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| `schedule-tool.ts`    | `schedule_task`: the model creates a scheduled task; the host saves it through the same path as the editor (`saveScheduledTask`). Not offered in scheduled runs.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| `todo.ts`             | `todo_write` checklist tool; the list is the call's arguments.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| `subagent.ts`         | `delegate_task`: isolated in-memory Pi session with read-only tools, limits and progress updates.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| `documents.ts`        | `read_document` tool: extracts text from office/PDF formats via officeparser inside the workspace.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| `attachments.ts`      | `buildPrompt`: turns attachments into image content or attached-file references; `splitAttachedFiles` for transcript display.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| `history.ts`          | Pure and file-reading helpers for chat history: accent/case-insensitive matching and snippets, `searchSessions` (streams session JSONL files newest first), pin keys, branch/entry-id helpers for message actions, `summarizeUsage` (tokens and cost). Tested in `history.test.ts`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| `export.ts`           | `conversationToMarkdown` / `conversationToHtml`: a conversation as a document (tool calls as short lines, no arguments or output). Tested in `export.test.ts`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| `transcript.ts`       | `Transcript`: the renderer-facing `ChatMessage` list built from Pi session messages and streaming events.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| `skills.ts`           | `SkillLibrary`: list/read/save/delete/enable skills, import from folder or `.zip`/`.skill` archive (with expansion limit), `validateSkillName`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| `mcp.ts`              | MCP servers: `McpConfigFile` (`mcp.json`), status parsing, `buildOverview`, `McpRegistrations` and `McpCommands` (save/delete/reconnect/sign in/out).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| `mcp-auth.ts`         | `VaultMcpAuthStore`: MCP OAuth state kept in the vault (`mcp-auth:state`) instead of Pi's plain `mcp-auth.json`, which it migrates and deletes.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
