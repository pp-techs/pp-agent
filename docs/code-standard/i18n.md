# Internationalization

The app ships in English (`en`, the fallback) and Vietnamese (`vi`). Every text a person reads goes through [i18next](https://www.i18next.com); the choice is **Settings › General › Language** (`System` follows the operating system), saved as `language` in `settings.json`.

## Where texts live

`packages/shared/src/i18n/locales/<lang>/<namespace>.json`, shared by every process. Namespaces: `common` (Cancel, Save…), `chat`, `settings`, `models`, `agents`, `extensions`, `modals`, `backend` (agent and main process). `createI18n` (`@workspace/shared/i18n`) makes one instance per process; each follows the language on its own.

| Process  | Translator                                                             | Follows the language                                                  |
| -------- | ---------------------------------------------------------------------- | --------------------------------------------------------------------- |
| Renderer | `useTranslation("<ns>")`; outside components `i18n.t("<ns>:key")`      | `LanguageSync` reads `AppSettings.language`; the title bar follows it |
| Agent    | `t("key")` from `agent/i18n.ts` (namespace `backend`)                  | `configureLanguage` at start (with `app.getLocale()`) and on change   |
| Main     | `translator()("key")` from `main/i18n.ts`, called at the moment of use | Reads `language` from `settings.json` on each call                    |

## Rules

- **Keys are typed from the English files**, so a missing key fails `vp check`. Vietnamese must mirror English (compile-time check in `resources.ts`, plus `i18n.test.ts` for placeholders and plurals). Vietnamese has no `_one` plural form, only `_other`.
- **Interpolate, never concatenate**: `t("deleted", { name })` with `{{name}}`; word order differs between languages. Use `<Trans>` for text with links or bold.
- **The model reads English.** `SYSTEM_PROMPT`, tool descriptions, approval-gate block reasons, and results of `read_document`, `web_search`, `web_fetch` stay English; so do `console.*` logs. Only text a person sees is translated.
- **Backend text that reaches the UI is translated by the backend** (errors become toasts). Data with a stable code is translated by the renderer instead: `ToolSummary.warning` is a code (`ToolWarning`), and agent tool options are looked up by tool name (`agents:toolOptions.<name>`), falling back to the backend text for unknown tools.
- **The shared UI library has no i18n dependency.** Its fixed labels (Close, Toggle Sidebar, Loading…) come from `UiLabelsProvider`, filled from `modals:ui.*` in the app.
- Use `i18n.language` for number and date formatting, never a hard-coded locale. Do not match on translated text in code (use data attributes or codes).
- Stored data is not translated: default agent and workspace names, session titles, user-written text.

## Adding a language

1. Add the code to `LANGUAGES` and its name to `LANGUAGE_NAMES` (`packages/shared`).
2. Copy `locales/en` to `locales/<code>`, translate, and register it in `resources.ts`.
3. Run `vp check` and `vp test`: missing keys and mismatched placeholders fail.
