# Business rules

Rules enforced in code. Paths are under `packages/agent-core/src/` unless noted.

## Approvals and tools (`tools.ts`)

| Tool tier | Tools                                                                                                                                                                                                                                                                                       |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| read      | `read`, `ls`, `find`, `grep`, `read_document`, `current_datetime`, `web_search`, `web_fetch`, `memory_list`, `memory_search`, `todo_write`, `delegate_task`, `ask_user`, `sessions`, discovery tools, `browser` looking actions, MCP tools with `readOnlyHint` from a server marked trusted |
| write     | `write`, `edit`, `memory_save`, `memory_forget`, `schedule_task`, `telegram_notify`, `browser` acting actions, every other MCP tool                                                                                                                                                         |
| exec      | `bash`, `powershell`, and any tool without a tier                                                                                                                                                                                                                                           |

| Tool policy    | Effect                                                    |
| -------------- | --------------------------------------------------------- |
| auto (default) | read tier runs; write and exec ask                        |
| ask            | always asks                                               |
| allow          | runs without asking                                       |
| off            | removed from the session and blocked in the approval gate |

- The shell (`bash`; `powershell` on Windows) is off by default. When **Settings › Tools** turns it on, every command asks, unless its policy is set to `allow` ("Run without asking"). The shell takes only `ask` or `allow`; choosing `allow` needs a confirmation that spells out the risk, and while it is set the Tools page shows a warning. The other platform's shell is always off.
- **Web search** (`web/`): `web_search` tries the enabled providers (SearXNG, Serper, Tavily, Brave, Exa, webclaw, DuckDuckGo) in the saved order, then the keyless ones (`KEYLESS_FALLBACK`: Exa through its public MCP server, DuckDuckGo's HTML page) that are not already in the list, so a saved key always goes first. It moves on when a provider fails or returns no results; the result names the provider and says `(no key)` when no key or server of the person's own was used. With nothing enabled the keyless ones still answer, so the search words go to Exa/DuckDuckGo; turning the `web_search` tool off is the way to stop that. Exa's keyless path ignores `recency`; DuckDuckGo answers 202 with a human check after a burst of searches, which counts as a failure (429) so the next provider runs. Keys sit in the vault under `websearch:<provider>`, never in `settings.json` and never in the renderer. `web_fetch` refuses non-http(s) addresses, embedded credentials, and any host that resolves to a private, loopback, link-local or metadata address (checked at connect time and on every redirect, up to 5); it reads at most 8 MB and returns Markdown (HTML, PDF, Office). HTML is converted by the bundled webclaw binary (`web/webclaw.ts`: HTML on stdin only, so webclaw never touches the network; it keeps the main content and drops menus), falling back to the whole-page conversion of `officeparser` when the binary is missing (Windows on ARM, a dev checkout without `vp run fetch:webclaw`), fails, or returns under 500 characters and the whole page is longer. Both tools wrap results in `<web_results>`/`<web_page>` and the system prompt tells the model that web text is data, not instructions.
- **Memory** (`memory.ts`, `memory-extraction.ts`): notes live in markdown files, one bullet per note (`- [tag] text`, pinned `- ! [tag] text`, newest last, other text untouched): `<user-data>/agent/MEMORY.md` and `<workspace folder>/.agents/MEMORY.md` (atomic write; re-read only when size or modification time changed), each in a place: everywhere (`workspaceId: null`) or one workspace, which is what a conversation sees (its own workspace's notes plus the global ones, never another workspace's). Each place holds at most 200 notes of 500 characters, labels of 30; the same note (ignoring case, spacing, closing punctuation) is stored once per place. `memory_save` takes `scope` (`global` or `workspace`) and an optional `pin`, and the tools never see another workspace's notes; `memory_search` matches words without accents. The `## Memory` prompt section (notes marked as user-provided data, never instructions, plus when to search and when to save) is taken at a session's first turn and kept for the session: the note lines budget 2000 characters (rules and markup outside the budget), pinned notes first, then `identity`/`preference` notes, then the newest of this workspace, then the newest global ones. The background pass runs on the fast model when a window conversation has been idle 5 minutes or is left (never for chats, scheduled runs, helpers, or a conversation being deleted), reads only messages after the branch's `pp-agent-memory` cursor, and applies at most 5 operations (add, update, delete) on the notes exactly as it saw them; it never changes a pinned note or one edited since, puts every note of the built-in Personal workspace in the global place, and cannot add to a full place. A chat's or a scheduled run's session carries a `pp-agent-origin` mark written at creation, so it is never read however it is reopened or whatever happens to the task or chat that made it (sessions from before the mark are excluded only while the chat or task record still points at them), and a pass still waiting on the model when its conversation is deleted applies nothing, and so does one whose Memory was switched off or that was still running when the app shut down (cancellation latches: switching Memory back on does not revive the pass). Its changes are announced (`memory_auto_saved`) and can be undone for 10 minutes (`undo_memory_pass`; a note changed since is left alone). Memory is on when Settings › Memory is on **and** the agent's `memory` field is true (missing = true); otherwise the section is absent, the memory tools are removed from the session, they refuse to run, and no pass runs. `memory_save` and `memory_forget` are write tier, so they ask under `auto`; the forget card shows the note's text. Deleting a workspace leaves its `MEMORY.md` in the folder. The global switch is `memoryEnabled` in `settings.json`.
- **Checklist** (`todo.ts`): `todo_write` replaces the whole list (≤ 30 items, status `pending`/`in_progress`/`done`). The chat reads the list from the call's arguments, so it is live while streaming and returns with the saved conversation. No approval.
- **Goals** (`goal.ts`): `/goal <objective>` (≤ 4000 characters; one goal per conversation) makes the agent carry on by itself after each turn until it calls `complete_goal` (read tier, active only while the goal is). Stopping or a failed turn pauses it, a turn without a tool call waits for the person, and a reopened conversation has its goal paused. Window conversations only.
- **Questions** (`ask.ts`): `ask_user` takes 1–5 questions, each with a unique `id` (≤ 40 characters), the question (≤ 300), 2–6 options with unique labels (≤ 80; description ≤ 200), optional `multi` and `recommended` (position from 0). The model may not add an option called "Other"; the window and Telegram add one for the person's own answer (≤ 2000 characters). A single-select question takes one pick or a typed answer, never both; a multi-select takes any mix; every question needs an answer before **Send**. The tool needs no approval and is registered only where a person can answer (the window and Telegram chats), never in scheduled runs or helpers. Skipping, stopping the run, or no answer in Telegram within 10 minutes ends the call with the error "The user chose not to answer."
- **Sub agents** (`subagent.ts`): `delegate_task` takes an optional shared `context` (≤ 8000 characters) and 1–5 `tasks`, each `{ task, agent?, name?, model? }`, and runs them at the same time, each in its own in-memory Pi session with its own short prompt, no extensions or skills, and only the read tools that run without asking under the current settings (`read`, `ls`, `find`, `grep`, `read_document`, `current_datetime`, `web_search`, `web_fetch`). `agent` names one of the person's Agents (case-insensitive; the tool description lists them): the sub agent then gets that agent's rules in its prompt, its model when usable (a task's own `model` wins), and only the tools that agent allows. An unknown name fails the whole call before any sub agent starts. Anything else, including memory, MCP and `delegate_task`, is blocked by a `tool_call` guard. Per sub agent: 25 tool calls, 12 tool turns, 5 minutes, then one wrap-up reply without tools. The result is one summary per task (headed `## <label>` when there are several; label = `name`, else the agent's name, else `Helper <n>`, made unique), 24000 characters shared across them; one failed sub agent is reported in its section and the others still return, and the call fails only when all fail. Stopping the parent run aborts every sub agent. Their status streams to the chat as a `HelperProgress` list per helper (working, done or failed, with its steps), shown under the step and in a panel above the message box while the call runs.
- `edit` is off by default; non-developers use `write`.
- **Computer use** (`computer-tool.ts`, `computer-apps.ts`): `computer` is off by default and listed as write tier; the approval gate rates each call by its action (`apps`, `windows`, `snapshot`, `screenshot` read; the rest write). It runs only in window conversations (blocked in chats, scheduled runs and helpers) and only while a window with cua-driver is connected. Protected apps (PP Agent, terminals and script runners, system and password settings) are always refused; blocked apps are refused; the first use of any other app in a conversation asks once (Allow once / in this chat / always). See [Computer use](../architecture/computer-use.md).
- Discovery tools (`codemode`, `tool_search`, MCP resource tools) are always allowed; the calls they make pass the gate individually.
- **File reads by path** (`path-access.ts`): the approval gate resolves the path of `read`, `ls`, `find`, `grep` and `read_document` (symbolic links followed, `~`/`@`/`file://` as pi reads them). Inside the workspace (or the installed skills folder) the usual rule applies; outside it the call asks even when the tool runs freely, unless yolo mode is on. The app's data folder (vault, keys, tokens, `mcp.json`, sessions) and `~/.ssh` are always refused, whatever the policy or yolo mode; a recursive `find`/`grep` of a folder that holds one is refused too. Helpers (`delegate_task`) read only inside the workspace. Scheduled runs deny the asks as before.
- **Browser** (`browser-tool.ts`): listed as write; the gate rates each call by its action: `tabs`, `select`, `snapshot`, `text`, `screenshot`, `scroll`, `wait` read; `open`, `navigate`, `back`, `forward`, `reload`, `close`, `click`, `type`, `press`, `select_option`, `eval` write (they ask under `auto`).
- **MCP read-only labels** (`mcp.ts`): a tool's `readOnlyHint` counts only when the person marked its server trusted (`trusted: true` in `mcp.json`, the switch in the server form, off by default); otherwise every tool of the server is write tier.
- **Chats other people talk in** (`index.ts`, `callRule`): a Telegram/Zalo chat that is not the owner's own private chat ignores yolo mode and asks the owner before every tool except discovery tools, `todo_write`, `ask_user` and `current_datetime`; with nobody paired those tools are off. Its prompt carries only the workspace's own memory notes, never the global ones; each message is prefixed with the sender's name and id; only the owner's messages steer or interrupt a running turn (others queue).
- **Approval cards** show the whole text of a call (no cut at 600 characters; the window card scrolls). Telegram (1500) and Zalo (1200) cards keep the start and the end around a "… N characters hidden …" line.
- **Sub agents under a named agent** get only the tools both that agent and the calling agent allow.
- Stopping a run denies all pending approvals and skips all open questions first.
- Telegram and Zalo `/pair`: besides the global lock after 5 wrong codes, a sender (user id) is locked out alone for 15 minutes after 3 wrong codes.

## Agents (`agents.ts`)

- The default agent (id `default`, "PP Agent", 🤖) always exists, can be edited, and cannot be deleted. If the active agent points nowhere, it falls back to the default.
- Deleting an agent: conversations using it fall back to the default; if it was the active agent or the open conversation's agent, those switch to the default.
- Names are unique (case-insensitive), at most 60 characters. Icon ≤ 8 characters (one emoji). Description ≤ 1000 characters. Instructions ≤ 20000 characters. At most 20 starter prompts, each ≤ 300 characters. Ids are `ag-<slug>`.
- Effective availability is Settings ∩ agent: an app tool is usable only if not off in Settings and in the agent's tools (`null` = all); MCP servers and skills likewise. Unavailable tools are blocked with "not available to <agent name>".

## Workspaces (`workspaces.ts`)

- A workspace is a folder plus defaults and rules for the chats started in it: name, icon, folder, and the agent new chats start with. Its rules are the `AGENTS.md` in the folder. (Earlier versions also kept a model and a thinking level per workspace; they were removed, and files that still have them are read without them.) The built-in workspace (id `default`, "Personal", 📁) uses the app's folder, can be edited, and cannot be deleted.
- A chat belongs to the workspace whose folder is its working directory. The folder is set when the workspace is created and cannot change afterwards; it must be an absolute path, is created when missing, files are refused, and no two workspaces share a folder. If it cannot be used at runtime, the default folder is used with a notice.
- Names are unique (case-insensitive), at most 60 characters. Icon ≤ 8 characters. Ids are `ws-<slug>`.
- New chats in a workspace start with its agent (else the agent picked last), the thinking level picked last, and a model chosen in this order: the agent's model, the default model.
- Rules come from `AGENTS.md` files, not from settings: Pi adds the `AGENTS.md` (or `AGENTS.override.md`, `CLAUDE.md`) in the folder and in every folder above it to the system prompt as project instructions, next to the agent's section. Settings › Workspaces edits the folder's own `AGENTS.md` (created when missing) and lists the ones loaded from outside it. Edits apply to the open chat once no run is active, and to other chats when they open. Older settings files kept `instructions` per workspace; at start they move into the folder's `AGENTS.md` (a new file, or a `## Workspace instructions` section appended to the existing one, once), or into `workspace-instructions-<id>.md` next to `settings.json` when the folder cannot be written.
- Skills in the folder's `.agents/skills` belong to the workspace and load next to the installed ones, so the layers run global (installed) → workspace → agent. A workspace skill wins over an installed one of the same name. The agent's skill list is the last, closest filter over both: a skill outside it is off in that agent's chats, whichever layer it comes from. Settings › Skills › off hides a skill everywhere. The agent editor lists installed skills and those found in every workspace folder.
- Deleting a workspace removes only the profile: its chats and files stay, and its chats are listed under the built-in workspace. Agents are not affected; deleting an agent clears it from the workspaces that started with it.

## Scheduled tasks (`scheduled-tasks.ts`, `scheduler.ts`)

- At most 50 tasks. Name unique (case-insensitive), at most 60 characters; prompt required, at most 20000 characters. Ids are `task-<random>`. An agent or workspace that no longer exists is replaced by the default one when the task runs.
- Schedules (local time): every 5–1440 minutes, every 1–168 hours, daily at `HH:MM` (24 h), or weekly on one or more weekdays at `HH:MM`. Anything else is refused.
- Runs happen one at a time, never twice for the same task at once, each in its own Pi session and saved conversation titled `⏰ <name> – <date>`, apart from the open conversation. A run is stopped after 30 minutes and recorded as failed.
- Unattended runs never approve anything: a tool call that would ask is denied (counted in `lastRun.deniedTools`) and the model is told. Only tools that run without asking (read tier under `auto`, or policy `allow`) run. Tools with policy `off` stay off.
- A slot missed while the app was closed runs once when the app starts if it was due within the last 24 hours; older ones are skipped. A task that is created, switched on, or whose schedule changes counts from that moment. Deleting a task stops its run in progress.

## Voice input (`transcription.ts`)

- Off until a provider is chosen in Settings › General › Voice input. Only a provider or gateway that has a key and an OpenAI-style address can be chosen; model ≤ 100 characters (default `whisper-1`); language `app` (the app's language, default), `auto`, or a two- or three-letter code.
- Recording: at most 5 minutes (a few seconds of slack), at most 20 MB, formats webm, ogg, mp4/m4a, mp3, wav. Longer or larger audio is refused with a message.
- The audio goes to `{provider base address}/audio/transcriptions` with the provider's key from the vault; the key and the audio never reach the settings file, and the renderer only receives the text. The text is inserted into the draft and never sent by itself.
- The app window may use the audio microphone permission only (`main/permissions.ts`); video and all other web permissions are refused.

## Skills (`skills.ts`)

- Name: lowercase letters, digits, single hyphens (`^[a-z0-9]+(-[a-z0-9]+)*$`), at most 64 characters — the same rule Pi applies.
- Description required, at most 1024 characters.
- Duplicate names are refused on import; archives > 100 MB expanded are refused.
- A workspace folder's own skills (`.agents/skills`) load only after the person trusts that folder (Settings › Workspaces, saved in `trustedSkillFolders`, off by default, only from the computer), and never replace an installed skill of the same name.

## MCP servers (`mcp.ts`)

- Server names: letters, digits, `_`, and `-` only (`^[A-Za-z0-9_-]+$`).
- Unknown keys in `mcp.json` entries are preserved.

## Conversations and defaults (`index.ts`)

- Attachments that are not model images are copied into `<workspace>/attachments/`.
- Each conversation remembers its model, agent, and thinking level.
- New chats use the last-picked agent (`activeAgentId`) and thinking level; the model is agent model → default model → first available.
- Settings changes apply to the open conversation without losing it; if the agent is busy, they apply when it finishes.
- Removing a provider that holds the default model clears the default model.
