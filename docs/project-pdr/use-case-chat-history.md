# Use case: chat history management

- Each conversation is a Pi session file (JSONL) in `<user-data>/sessions/`.
- The sidebar groups saved conversations by workspace (collapsible, the built-in workspace first); inside each workspace they are listed by date. The `+` on a workspace starts a new chat there; the user opens, renames, or deletes chats from the list.
- Titles are derived from the first message and cut to 80 characters (`sessionTitle` in `packages/agent-core/src/history.ts`).
- Each conversation remembers its model, agent, and thinking level; opening it restores them (model only if still available; deleted agent → default agent).
- `/new` and the sidebar's **New chat** start a new conversation in the open conversation's workspace; new chats use that workspace's agent when it sets one, else the last-picked one, and the last-picked thinking level (see `business-rules.md`).
- **Search.** The box at the top of the sidebar (debounced) runs `search_sessions`: every word must occur in the title or in one message, ignoring case and accents (so `viet` finds "Việt"). Titles and the person's own words, assistant text and attached file names are searched; tool results are not. Files are read newest first, a few at a time, line by line, and reading stops at 40 matches, so it stays quick with hundreds of chats. Queries under 2 characters are not searched. Results show the title and a snippet with the matches marked; selecting one opens the chat.
- **Pin.** _Pin_ / _Unpin_ in a chat's menu. Pinned chats are listed in a "Pinned" group above the workspaces (not repeated under their workspace). Pins are stored in `settings.json` (`pinnedSessions`, by file name) and cleared when the chat is deleted.
- **Export.** _Export_ in a chat's menu and the download button in the header save the conversation as Markdown (`.md`) or a printable web page (`.html`) through a native save dialog. The file has the title, workspace, date, the person's and the assistant's text, attached file names, and one short line per tool call (tool name and, for file/URL/search tools, the file, page without query string, or search words). Commands, tool arguments, tool output, and thinking are never exported. DOCX is not offered.
- **Message actions.** Under each message (visible on hover or focus): _Copy_ the text; _Edit and resend_ (own messages: change the text, remove or add attachments, then the message and everything after it are replaced; the old version stays in the file as another branch); _Regenerate_ (last answer: the same message is sent again); _Branch into a new chat_ (a new conversation with the chat up to and including that message, opened right away). Editing, regenerating and branching are refused while an answer is being written.
- **Usage and cost.** The context button in the header shows input, output, cache read/write tokens and an estimated cost for the whole conversation, including messages a compaction summarized away. Cost comes from the price Pi knows for each model; replies from models without a price are left out and the cost reads "unknown" (or "+ unpriced replies" when only some had no price). Numbers follow the app language.

Pi writes a session file only once the conversation has an assistant message, so a chat with no answer yet does not appear in history. Entries added before that (such as the `pp-agent` agent entry) are kept in memory and written with the first answer.
